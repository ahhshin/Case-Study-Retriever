# Retrieval harness and simple GUI

## Try it without installing anything

Download `web/demo.html` from this branch and open it in Chrome. It contains the ten metadata records and works offline; opening a source link requires internet access. Try “find me a case study about luxury brands”: Burberry is returned with its page-48 evidence. This demo is metadata search, not a live model. It cannot accept API credentials.

Rebuild it after changing metadata, aliases, or the interface with `case-demo`. Its browser ranker mirrors the Python baseline; shared alias and stopword configuration is generated by the exporter. Do not edit the embedded records by hand.

## Run the Python harness and GUI

From the repository checkout:

```bash
pip install -e .
case-search "find me a case study about luxury brands"
case-serve
```

Open http://127.0.0.1:8765. This version calls the Python harness. It needs the committed processed metadata; default search does not require downloaded PDFs or API keys. Run `case-ingest` before a model adapter needs full page reads.

The local HTTP server is a prototype, bound only to loopback. It is not a production deployment. The standalone demo can be served as a static page; a live model GUI needs a Python host.

## Plug in any model

The harness does not import a provider SDK. An adapter exposes exactly one method:

```python
class MyAdapter:
    def complete(self, messages: list[dict[str, str]]) -> str | dict:
        # Call your chosen SDK or HTTP endpoint here.
        # Return the assistant text containing the JSON action,
        # or return the decoded JSON action object.
        return your_provider_call(messages)

def create_adapter():
    return MyAdapter()
```

Launch with `case-serve --adapter my_adapter:create_adapter` or `case-search "luxury brands" --adapter my_adapter:create_adapter`. The factory takes no arguments; configure credentials/model names in server-side environment variables. Credentials are never accepted by or embedded in the GUI. `CallableAdapter` also wraps an existing SDK callback directly.

For CLI-driven models, `CommandAdapter` sends `{ "messages": [...] }` to an executable's stdin and expects one JSON action on stdout. Set `CASE_MODEL_COMMAND` to a JSON argument array and use `--adapter case_studies.adapters:from_environment`. The executable must adapt the chosen CLI/provider to this contract. No shell interpolation is used. Provider availability and credentials must be verified separately.

## Model execution contract

Each request starts with the compact catalogue. A provider-neutral JSON protocol allows three actions: `read_case`, `read_pages`, and `final`. The system prompt in `retrieval.py` gives the exact contract. Messages use ordinary system/user/assistant strings; adapters may translate these into any provider's native format. Native vendor tool-calling APIs are not required.

The harness limits execution to eight model calls by default, constrains page reads to selected source pages, and requires the model to open each selected record. Final selections contain known case IDs and evidence IDs. Summaries, metrics, quotes, and URLs are rendered from stored records, never generated by the model. Invalid actions, unknown evidence, and exhausted budgets fail explicitly; there is no silent fallback from a failed model to baseline search.

Evidence ID validation prevents fabricated quotes from appearing, but cannot prove the model's relevance judgment or that each selected quote fully supports the query. Inspect the evidence and limitations. An empty final selection means no match. Model integration was tested with scripted provider-independent adapters; no real paid provider call has been made.

## Baseline behavior and limitations

Default retrieval uses controlled-tag synonyms plus keyword overlap in titles, summaries, and inferred concepts. An explicit luxury request requires the observed luxury tag; it does not turn Jura's premium positioning into luxury. Explicit AI requires AI technology evidence. Recognized intents act as required tags, so a marketing-content query does not return software backlog generation merely because both mention AI. Scores are ranking heuristics, not confidence probabilities. Unknown requests can return no match.

The baseline handles the included examples and common related terms, but is not a general language understanding model: nuanced constraints, negation, and unseen paraphrases should use a model adapter. The ten records are assistant-curated drafts and their metrics are publisher-reported. No vector database is needed.

## Validation

Run `python -m unittest discover -s tests -v`. Tests cover luxury, SDLC, marketing, unrelated requests, model read/final flow, abstention, fabricated evidence, unread cases, selected-page limits, and budget exhaustion, alongside metadata integrity checks.
